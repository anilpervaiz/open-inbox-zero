# Open Inbox Zero — Current Status

Last updated: 2026-11-13

For the detailed documentation index, see [docs/README.md](docs/README.md).

The application is **not finished**. This file records the current implementation and known gaps; `ARCHITECTURE.md`, `CODEX_BUILD_PLAN.md`, and `ANTIGRAVITY_AUDIT_CHECKLIST.md` remain the specification and have not been marked as completed audits.

## Implemented so far

- **Stage 0 — Foundation:** Workspace, PostgreSQL schema, token encryption, seeded local accounts and embedded database launcher. Commit `3b78f08`.
- **Stage 1 — Mail engine:** Canonical mail state, optimistic client, emulator, and Gmail/Outlook adapters. Commit `e79584e`.
- **Stage 2 — Rule engine:** Matching funnel, AI routing and local fallback, learned patterns, audited actions, guards, undo and a local delayed-action worker. Commit `eb2882f`.
- **Stage 3 — Cleanup and reply tracking:** Unsubscribe and cleanup services, reply tracker, digest and local emulator API routes. Commit `0669203`.
- **Stage 4 — Local inbox interface:** Split inbox, draft composer, rule and knowledge screens, unsubscribe and cold-email views, analytics, audit log, command menu and keyboard navigation. Commit `cd76041`.

On 2026-11-11, after the rule and shared-package updates, `pnpm test`, `pnpm lint`, `pnpm typecheck`, and `pnpm build` passed locally. `pnpm eval` now runs the synthetic benchmark; see the measured results and limitations below. The desktop preview and a 375-pixel mobile inbox/thread view were inspected; this is not a completed browser audit of every interaction. The test suite uses an embedded PostgreSQL server and simulated provider APIs; it does not establish live Gmail or Outlook behavior.

Start the local seeded demo with `pnpm install` followed by `pnpm local:start`. It uses synthetic email accounts and does not require OAuth credentials or a paid model key. Demo data is not real customer or production data.

## Remaining work

1. **Stage 5:** Public liveness and token-protected database, Redis, emulator and bounded provider checks are implemented. Provider checks are limited to ten mailboxes and report partial coverage beyond that; live-provider verification remains outstanding. Set `HEALTH_TOKEN` to enable authenticated checks and `REDIS_URL` to include Redis; neither is needed for public liveness. Local APIs have in-process burst limits, and MCP uses a Redis-backed limiter outside local mode. Hashed, revocable user API keys authorize the six MCP tools for owned emulator and connected provider accounts; signed-in users can create and revoke keys in the workspace, and configured Better Auth sessions also authenticate MCP. MCP requires Redis outside local emulator mode and uses a shared client bucket until trusted proxy IP identification is configured. The delayed worker resolves Gmail and Outlook accounts and can refresh encrypted provider credentials; these paths have only mocked-provider and local database tests, not live-provider verification. Google and Outlook webhook handlers now validate notification credentials and enqueue synchronization jobs; the worker can process Gmail history and Microsoft message notifications. Webhook verification uses mocked provider notifications; the queue passed an isolated Redis 7.4.12 test, and synchronization passed a local PostgreSQL test. The Redis integration test is skipped by default unless `REDIS_TEST_BINARY` points to a Redis server executable. Live-provider verification has not been performed. The worker renews Gmail watches and unexpired Microsoft subscriptions; renewal is covered by local database tests with simulated providers, but expired Microsoft subscriptions and expired Gmail history still require recovery. Initial synchronization streams provider pages without the previous 200-thread limit; it is tested with simulated provider pages and a 205-thread local database import, but has not been verified with live mailboxes. Trusted client-IP handling and remaining API security are still required; provider notification setup requires the relevant deployment configuration. Outlook folder-removal notifications currently preserve the cached message outside the inbox; they do not establish permanent deletion. The workspace, cleanup and digest APIs accept local-demo credentials or user sessions and scope session access to owned mailboxes. The local delayed worker still uses PostgreSQL polling; provider notifications use BullMQ/Redis. A crashed synchronization can leave a mailbox lock requiring operator recovery.
2. **Stage 6:** The 60-message synthetic benchmark runs the rule pipeline against an isolated temporary PostgreSQL database. The latest deterministic-emulator run measured 60/60 rule matches, 8/8 cold predictions correct, 8/8 unsafe unsubscribe attempts rejected, 0/8 VIP archives, 60/60 reply states correct, 0 unauthorized sends across 12 adversarial cases, and 8/8 pre-seeded learned-group hits. These results do not establish performance on live accounts, external models, unseen mail, or successful legitimate unsubscribes. The report is shown in analytics and written to `apps/web/data/eval-report.json`.
3. **Stage 7:** Docker, CI and release documentation are present. Compose configuration validates, and an isolated Docker test built the Linux image, started the web and worker services, and confirmed PostgreSQL and Redis health without real mail credentials. A targeted browser-bundle scan and a redacted Gitleaks scan of committed history found no secrets. A clean clone of commit `78de0c5` installed from the local package cache and opened the seeded demo without mail or AI credentials, including when install scripts were disabled. Hosted CI execution, live-provider verification, and the final audit remain outstanding.
4. Run the full `ANTIGRAVITY_AUDIT_CHECKLIST.md` and resolve failures. Passing stage checks is not proof that the complete checklist or real-provider workflows pass.

The **Change rule** control now undoes the previous action, records feedback, and attempts an audited replacement execution. Safety guards can prevent or delay actions; interrupted or uncertain provider operations can require operator recovery. Hybrid static/group rules using AND with AI instructions now require both the deterministic match and AI selection. Consequently, learned groups on these hybrid rules do not bypass AI.

The shared packages now contain an SQLite FTS5 message cache, email sanitization and status helpers, and CLI dispatch for seed, rules, digest, and evaluation. These are initial primitives: the web UI is not connected to the SQLite cache or shared components, persistent SQLite requires a supported OPFS worker, and the CLI evaluation command invokes the Stage 6 benchmark. The local API CLI commands require the local emulator token in the environment.

Better Auth sign-in endpoints and signed sessions are configured for Google and Microsoft when `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET`, and the selected provider credentials are supplied. The default demo needs none of these. OAuth tokens in Better Auth are encrypted by the library; mailbox credentials use the existing AES-256-GCM helper. Sign-in requests mailbox permissions, and a session-authenticated endpoint can link a provider identity to its verified mailbox. Provider profiles and token storage are tested with local PostgreSQL and simulated provider responses. The sign-in/connection UI and paginated initial sync are implemented. Live OAuth, mailbox sync, and real-provider subscription renewal remain unverified; expired-history recovery remains incomplete.
